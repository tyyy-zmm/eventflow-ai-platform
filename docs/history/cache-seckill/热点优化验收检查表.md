# 热点优化验收检查表

用于复核本轮证据，不把计划项目误写成已实现能力。

| 检查项 | 通过条件 | 证据位置 |
|---|---|---|
| 保留一致性入口 | 受理、建单仍以活动行锁串行化；状态条件与唯一约束未删 | Trading.java，TradingTest，可靠性与中间件测试 |
| 返回值与提交一致 | 精简和旧路径的返回值与数据库已提交结果相等；取消后重放不改变终态 | TradingTest.compactAndLegacyReturnCommittedStateAndPreserveTerminalReplay |
| 对账不会无界遍历 | SQL 带主键游标及 LIMIT；每轮活动数和动作数分别受限 | Reservations.java，ReservationsPagingTest |
| 未访问活动不被跳过 | 动作预算耗尽时游标只推进至实际访问过的活动 | ReservationsPagingTest.actionBudgetDoesNotSkipUnvisitedActivity |
| 固定历史数据量 | 每个对照试验清理后六张核心表行数等于试验前 | hotspot-controlled 结果 historyBefore/historyAfterCleanup |
| 长时负载完整计数 | 计划 = 发出 + 生成器跳过；成功、拒绝与传输错误全部列出 | hotspot-long 结果与逐请求原始样本 |
| 不混淆完成定义 | HTTP 202、请求 SUCCEEDED、订单当前状态分别统计 | results.json、orderStates、报告口径说明 |
| 积压可收敛 | 停止到达后待请求、未发送 Outbox、未应用补偿归零 | 排空检查与 queuesAtHttpEnd |
| 故障无重复建单 | 有积压发送崩溃后原键重放仍为同一请求，库存约束通过 | pipeline-crash 原始结果 |
| 旧证据不覆盖 | 不把上一轮缓存/参数实验的指标归入当前二进制 | 各 evidence 的环境、日期和 SHA-256 |

自动清理生产历史订单、无限规模活动恢复、分桶库存、多 broker 容灾、长期 Prometheus/Grafana 部署均不属于本轮已交付能力。
