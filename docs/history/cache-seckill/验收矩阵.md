## 特别避免的结论

1. 本地 16 线程并发不等于 1000 个同时运行的线程，也不等于生产高并发部署。
2. 异步接口的 202 不是订单成功；同步 200 也需要看业务 state。
3. 少量库存下的高拒绝 QPS 不是订单 TPS。
4. 缓存低 SQL 次数不自动说明更好的正确性；更新竞争、失效持久化和锁归属须单独验证。
5. 默认单 Broker acks=all 不代表能抗 Broker 磁盘永久损坏。
6. Kafka 崩溃恢复可能受默认消费者会话超时影响，需要等待组重新分配；不能用已经落库的订单状态替代消费位点追平验证。
7. 测试只面向本地模块；原版网页/Agent 还未接入升级接口。
