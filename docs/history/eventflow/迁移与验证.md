# EventFlow迁移与验证

## 当前入口与状态

以下旧章节保留早期“只写代码”阶段的记录，不代表目前状态。本机已经安装 Java17、Maven、Docker 和真实 MySQL/Redis/Kafka，统一验收入口为：

```bash
bash scripts/local.sh pre-ai
```

该入口加载本地 `.env`，串行执行常规测试、五组真实集成测试、中间件停机恢复、任务进程崩溃恢复、缓存负载矩阵及 MySQL 备份恢复。最终状态以 `experiments/pre-ai-*/results.json` 为准；FAIL 报告和未运行用例不能作为完成证据。所有规划调用均为 disabled 或 stub，不调用真实模型。

当前迁移为 V1~V10，旧版本未改写：V8 修正 Outbox 三元身份并补充隔离消息位置/摘要，V9 增加任务 attempts，V10 增加管理员分页索引。管理员列表已改为 `{items,nextCursor}` 签名 keyset 分页；Outbox/重放/缓存失效具备租约与重试抖动。观测接入 lag、固定任务标签、503窗口、到期延迟、补位计时、告警抑制/恢复。通知为日志和可配置本地文件，未对接飞书、邮件或生产告警平台。

MiddlewareIT 使用本轮随机 topic/group，类结束后关闭应用上下文。测试发布器通过 `eventflow.test-outbox.started-at` 只领取数据库时间边界之后创建的事件，进程实验同样设置这一边界；默认空值即正常不过滤，非空只允许 eventflow_it。边界取数据库当前时间后2秒，等待2100ms后才创建 fixture，不能以随机场次ID划分新旧数据。上述实验关闭不属于测试目标的历史重放发布器；真实重放另由 DeliveryRecoveryIT 验证。历史故意构造的冲突消息保留，不混入本轮发布。该参数不得用来跳过生产积压。

新增故障点 `planning-after-claim` 在领取提交后、engine前真实 halt(137)，正常 deadline 后任务终结，两个扫描周期内 attempts 仍为1。单 broker、本机短时实验不能推导生产容量、副本容灾或SLO。真实模型协议、效果、成本及消融留在下一阶段。

## 外部模式

环境在另一台电脑准备；只使用独立数据库，禁止指向旧点评库或生产库。Flyway管理V1到V7。项目不会自动加载.env，请自行export：

| 环境变量 | 要求 |
| --- | --- |
| EVENTFLOW_DB_URL | jdbc:mysql://127.0.0.1:3306/eventflow?serverTimezone=UTC |
| EVENTFLOW_DB_USER / EVENTFLOW_DB_PASSWORD | 独立数据库账户 |
| EVENTFLOW_REDIS_HOST / EVENTFLOW_REDIS_PORT | 默认127.0.0.1 / 6379 |
| EVENTFLOW_KAFKA_SERVERS | 默认127.0.0.1:9092 |
| EVENTFLOW_CURSOR_SECRET | 至少32 UTF-8字节；双实例必须相同，随机默认值不支持跨实例游标 |
| EVENTFLOW_LOCAL_USER_PASSWORD / EVENTFLOW_LOCAL_ADMIN_PASSWORD | 显式账户预置时需要，无默认密码 |
| EVENTFLOW_PLANNING_MODE | disabled/stub/deepseek；默认disabled |

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=external \
  -Dspring-boot.run.arguments="--eventflow.local-accounts.enabled=true"
```

默认监听127.0.0.1:8091，Demo保持关闭。external开启Redis/Kafka/后台，依赖不可用会失败/重试。第二实例指定--server.port=8092，共享DB/Redis/topic/consumer group/游标密钥。

真实模型另需DEEPSEEK_API_KEY和EVENTFLOW_MODEL，没有默认模型名称。固定官方HTTPS地址；协议依据：[DeepSeek官方API](https://api-docs.deepseek.com/api/create-chat-completion/)。启用会发送偏好及候选资料并产生费用，本轮没有调用。stub不是效果数据。结构化约束必填，自由文本仅作偏好，不是自动约束提取；三个LLM角色由Java编排，不能包装成四个LLM。

## 真实集成入口

仅使用空的、独立、可丢弃eventflow_it数据库和独立Redis/Kafka测试环境。会写入业务表和测试topic，不自动清库：

```bash
export EVENTFLOW_INTEGRATION=true
export EVENTFLOW_IT_DB_URL='jdbc:mysql://127.0.0.1:3306/eventflow_it?serverTimezone=UTC'
mvn -Dtest=MiddlewareIT test
```

另需DB账户及中间件变量。IT启动前检查loopback URL及eventflow_it库名，测试内再次检查SELECT DATABASE()。关闭过期/补偿/清理扫描，Kafka转发仍运行，避免扫描掩盖消息链路失败。目前只有释放→候补补位及目录更新→真实Redis失效两个用例，不是完整故障矩阵。

## 进程故障实验

FaultPoints默认关闭，无公开HTTP开关，只允许eventflow_it。启动参数--eventflow.test-faults.enabled=true，EVENTFLOW_FAULT_POINT选一个：

| 值 | 中断位置 | 恢复核验 |
| --- | --- | --- |
| reservation-after-commit | 正式预约提交后响应前 | 原key返回同一预约，不重复扣库存 |
| outbox-after-send | broker确认后发布标记前 | 租约到期原ID重发，无重复业务效果 |
| consumer-after-commit | 实际补位提交后ack前 | 重投命中Inbox，不再次补位 |

命中会Runtime.halt(137)，立即终止进程且不优雅关闭。仅在可丢弃数据上运行；先备份。重启撤掉开关/变量，否则再次命中仍退出。忽略仅取消待发重放，不能撤回在途消息。

每次保留源eventId、topic/partition/offset、请求键、SQL状态、故障及恢复时间线。最多等待5分钟，未收敛计失败；/api/v1/admin/invariants各项为0并独立SQL对账。故障点代码不是已执行实验报告。

## 只读压测

Node需支持fetch和AbortSignal.timeout。先发布有效场次并登录取得token：

```bash
export EVENTFLOW_TEST_TOKEN='替换为本机测试会话token'
export EVENTFLOW_BENCH_SESSION=1001
export EVENTFLOW_BENCH_URLS='http://127.0.0.1:8091,http://127.0.0.1:8092'
export EVENTFLOW_BENCH_RATE=20
export EVENTFLOW_BENCH_SECONDS=180
node scripts/read-benchmark.mjs
```

仅loopback正式详情GET，最多128在途；metrics.json保存状态、客户端丢弃、调度延迟、全部/成功请求p95/p99和原始记录。不自动预热/重置，不含交易压测。缓存开/关用相同数据、机器、速率和时长，预热后重复至少三轮。503/429/客户端丢弃不能计成功吞吐。正式命中仍查询DB发布状态，不能预设提升比例。

## 剩余设计细项与实验

- 增强观测未完成：consumer lag、缓存命中率、最近任务成功时间、告警抑制/恢复通知及外部投递。目前只有基础Gauge、日志告警及守恒检查。
- 搜索支持city、from/until时间窗口及分页，HTTP时间参数需带时区；管理员异常/审计列表仅最多100条，没有完整分页后台。
- 分层准入已实现：每用户每接口60次/分钟、每用户每场次5次/10秒及每活动默认200次/秒，Lua返回PTTL，正式API保留实际Retry-After。三个窗口不是联合扣费，也不是令牌桶或严格公平调度。
- 源Outbox有指数退避，缓存/重放主要等租约；完整随机抖动未实现，非法消息不保留原始payload全文。
- Outbox唯一键仍event_type+source_id，当前源转换每类型只生成一次；不是含revision的通用事件日志。
- 真实MySQL迁移/锁竞争/EXPLAIN、双实例交易、Kafka故障/再均衡、Redis恢复、备份恢复、模型协议及效果/消融均未执行。

另一台电脑优先构建→MiddlewareIT→交易竞争/响应丢失→消息故障→缓存对照→模型评测。只有真实原始证据支持的结果才能写入简历。
