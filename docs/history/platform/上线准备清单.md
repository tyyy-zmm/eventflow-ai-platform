# 上线准备清单

## 当前已经具备

- 前后端同源部署、HttpOnly Session、CSRF 和同源写保护；
- Flyway 增量迁移，Redis AOF，MySQL/Redis/Kafka 数据卷；
- Redis Lua 准入、MySQL 交易兜底、Kafka 至少一次和业务幂等；
- 补偿任务、超时扫描、对账、隔离消息和管理员重放；
- 有界线程/连接/队列、积压保护和依赖超时；
- Docker 健康检查、Actuator readiness/liveness、Prometheus 指标出口；
- 单元测试、真实中间件测试、故障注入和容量实验脚本；
- GitHub Actions 后端测试、前端构建与镜像构建检查。

## 公开部署前必须完成

1. 使用云密钥服务或 Docker Secret 管理数据库、Redis、Session 和模型密钥；
2. 接入 HTTPS，将 `COOKIE_SECURE=true`，确认反向代理的 Host/Proto 可信配置；
3. MySQL 自动备份与恢复演练，设置 binlog、备份保留期和恢复目标；
4. Redis Sentinel/Cluster 与 Kafka 三副本，重新执行故障和数据丢失测试；
5. Prometheus/Grafana 告警：错误率、P95、连接池、Outbox 积压、Kafka lag、补偿积压和对账异常；
6. 替换本地账号为正式身份体系，增加密码找回、验证码、风控和审计保留策略；
7. 引入真实支付前设计支付幂等、签名验证、退款、关单和资金对账；
8. 进行依赖漏洞扫描、SAST、容器镜像扫描和渗透测试；
9. 压测独立部署负载器，按目标机器和业务比例重新确定容量与限流阈值；
10. 建立灰度、回滚、数据库向前兼容迁移和事故响应手册。

## 不应对外声称

- 单机实验 QPS 等同生产容量；
- Kafka 或 Redis 天然保证 exactly-once；
- 通过当前测试就代表多区域容灾完成；
- Agent 的规划结果等于名额已经锁定或订单已经成功。
