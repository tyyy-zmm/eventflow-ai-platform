# 秒杀链路与代码对照

本文说明简历中的秒杀方案如何落到当前代码，避免“描述一套、实现另一套”。

## 完整链路

```text
POST /v2/requests
  -> Auth：Session、CSRF、同源校验、用户级限流
  -> Reservations：Redis Lua 原子校验一人一单、请求幂等并预扣库存
  -> Admission：用户/活动限流、积压保护、售罄快速失败
  -> Trading.accept：MySQL 事务写 ux_request + ux_outbox
  -> Delivery.relay：Outbox 租约领取、重试发送 Kafka、成功后标记 sent_at
  -> Delivery.consume：校验事件并调用 Trading.process
  -> Trading.processLocked：MySQL 条件扣减、唯一约束、事务建单
  -> ux_reservation_action：记录 CONFIRM / RELEASE / RESTORE
  -> Reservations.drainActions：幂等同步 Redis 预扣状态
  -> Delivery.expire + Reservations.reconcileStale：超时处理与异常对账
```

## 简历表述与实现

| 简历能力 | 代码与数据表 | 正确性边界 |
| --- | --- | --- |
| Redis Lua 防超卖、一人一单 | `Reservations.RESERVE`；库存 String、用户 Hash、请求状态 Hash、待处理 ZSet | Redis 在入口原子预扣并拦截无效流量；最终交易正确性仍由 MySQL 兜底 |
| MySQL 交易一致性 | `Trading.accept/processLocked/transition`；`ux_request`、`ux_order`、`ux_activity` | `available > 0` 条件扣减防止负库存；`UNIQUE(activity_id,user_id)` 防重复订单；请求幂等键防重复受理 |
| Kafka 异步建单 | `Trading.accept` 同事务写 `ux_outbox`；`Delivery.relay/consume` | Outbox 避免“数据库提交但消息丢失”；Kafka 至少一次投递，消费端状态机和唯一约束保证业务幂等 |
| Redis/MySQL 最终一致 | `ux_reservation_action`、`Reservations.APPLY/drainActions/reconcileStale` | MySQL 事务只记录补偿意图，不跨系统强行做分布式事务；后台重试和对账最终确认或回补 Redis |
| 故障恢复 | Outbox 租约、指数退避、请求截止时间、毒消息隔离、超时扫描 | 进程可在发送前后、消费提交前后中断；重启后从持久状态继续，不承诺跨系统 exactly-once |

## 关键场景

1. **重复点击或响应丢失**：同一 `requestKey` 重放返回原请求；若相同键对应不同活动，则拒绝为幂等冲突。
2. **Redis 预扣后进程宕机**：预扣项保留在待处理 ZSet；若 MySQL 没有请求记录，对账执行 `RELEASE` 回补库存并释放购买资格。
3. **MySQL 已受理但 Kafka 不可用**：请求与 Outbox 在同一事务提交；Relay 按指数退避重试，用户可继续按请求键查询状态。
4. **Kafka 重复投递**：已离开 `ACCEPTED` 的请求直接返回；数据库唯一约束再次阻止重复订单。
5. **建单失败或超时**：事务写入 `RELEASE` 动作，后台幂等执行 Redis 回补。
6. **用户取消或确认超时**：MySQL 回补库存并写 `RESTORE` 动作，Redis 随后恢复库存，但保留一人一单语义。

## 可验证证据

- `TradingTest`：条件扣减、重复消费、取消/过期和状态机；
- `MiddlewareTest`：真实 MySQL、Redis、Kafka 下的并发与故障场景；
- `scripts/redis-db-benchmark.mjs`：Redis 前置前后的数据库访问量 A/B；
- `scripts/full-chain-benchmark.mjs`：受理、异步建单、最终状态和不变量；
- `scripts/faults.mjs`：Kafka/Redis 中断、提交与应答窗口、补偿和对账；
- `docs/Redis_Kafka_MySQL全链路实验.md` 与 `docs/库存不变量说明.md`：实验口径和结果边界。

面试时应明确：Redis 的目标是快速准入和削峰，MySQL 决定最终订单与库存是否正确，Kafka 负责把建单移出请求线程，补偿任务与对账负责跨系统最终一致。
