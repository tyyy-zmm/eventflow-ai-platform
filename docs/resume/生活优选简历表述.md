# 生活优选简历表述

## 一页简历版本

**生活优选：优惠券秒杀与多级缓存平台**｜2026.03-2026.10

提供商家查询、优惠券秒杀、异步建单、订单取消、模拟支付和超时关单等功能。

- 商家查询采用 **Caffeine → Bloom Filter → Redis → MySQL** 链路，软过期时返回旧值并异步重建，Redis 异常时限制数据库回源；同机正常登录、多商家 A/B 中，P95 中位数从 **1.882ms 降至 1.707ms**，吞吐中位数从 **6,204 req/s 提升至 8,396 req/s**。
- 基于 **Redis Lua** 实现库存预扣和一人一单校验，MySQL 通过条件扣减和唯一索引防止超卖和重复下单；通过持久化补偿任务处理请求中断及服务重启后的库存恢复。
- 基于 **Outbox + Kafka** 实现异步建单，消费端根据请求状态避免重复建单；库存扣减与订单写入的事务提交后才确认消息处理完成，消息发布失败自动重试。
- 基于 **Redis ZSet 和持久化任务**实现延迟关单，通过 **CAS 条件更新**处理模拟支付与关单并发，防止订单状态覆盖及库存重复回补；支持遗漏任务补偿和关单后付款的退款处理。

## 数字使用条件

本轮采用正常 Cookie 会话、20 个商家轮询、两个 384MiB JVM、总并发 8，每模式 30 秒 × 3 轮，比较 Redis TTL 与多级缓存。两项指标均为三轮中位数，不是最佳单轮；仍只描述商家基础信息接口，不能写成整站、完整详情页或秒杀 TPS。Redis 基线有 5 次 HTTP 503（约 0.0011%），多级缓存无失败，不能把基线描述为零错误。逐轮波动和全部结果见[复核记录](../verification/2026-10-03-cache-payment-audit/README.md)。

旧版 2.34 倍和 48.3%来自单热点、测试令牌鉴权。新的单热点复跑为 2.26 倍、P95 降低 48.7%，不与 Cookie 组混用。由于本机负载波动明显，这些数字表示受测条件下的观察，不是稳定生产容量承诺。

本轮 138 项后端测试通过，包括真实中间件和支付 HTTP 测试。此前 9 组浏览器流程属于上一轮验收，本轮未修改前端或重跑浏览器。测试数量不代表生产流量。当前订单查询是一个物理 MySQL 内的 32 张表，当前 ID 为 UUID。支付为模拟渠道，没有真实支付验签、资金清算或第三方退款 API。
