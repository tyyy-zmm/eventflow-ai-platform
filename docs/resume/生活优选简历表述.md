# 生活优选简历表述

## 一页简历版本

**生活优选：优惠券秒杀与多级缓存平台**｜2026.03-2026.10

基于黑马点评改造商家查询与优惠券秒杀，完成登录、异步建单、确认取消、历史订单查询与故障恢复闭环。

- **多级缓存：**构建 Caffeine、Redis、MySQL 三级读链路，引入 Bloom、防击穿锁、软硬过期与有界降级；本机双实例、总并发 8、每模式 30 秒 × 3 轮对照中，多级缓存 QPS 中位数为 Redis TTL 的 **2.34 倍**，P95 降低 **48.3%**。
- **秒杀一致性：**通过 Redis Lua 完成库存预占与一人一单校验，MySQL 活动行锁、条件扣减和唯一约束完成最终裁决；持久化补偿任务与 epoch 恢复处理宕机、取消和超时回补。
- **可靠异步建单：**将请求与 Outbox 在同一事务落库，Kafka 按活动分区异步建单，使用发布租约、提交后确认、业务幂等和毒消息隔离保证重复投递与重启下订单效果一致。
- **查询与观测：**将历史订单投影到按用户路由的 32 张查询表，利用版本号防重复及状态倒退，并以游标核对自动补数；接入 Micrometer、Prometheus 和 Grafana 观测缓存熔断、Outbox 与投影积压。

## 数字使用条件

2.34 倍和 48.3%只描述商家基础信息接口的本机热点读取，环境是双 JVM、每个堆 384MiB、总并发 8、每模式 30 秒 × 3 轮；不能改写成整站 QPS、详情页 QPS 或秒杀 TPS。数据库直读对照为 2.84 倍、P95 降低 54.3%，简历选 Redis TTL 作为更严格基线。

125 项后端测试和 9 组浏览器流程是测试数量，不代表生产流量。当前订单查询是一个物理 MySQL 内的 32 张表，不能说成四库八表或 ShardingSphere。当前 ID 为 UUID，未实现 Snowflake。
