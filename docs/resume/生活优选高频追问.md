# 生活优选高频追问

当前压测数字和误差以[复核记录](../verification/2026-10-03-cache-payment-audit/README.md)为准。

1. **为什么 Bloom 判断不存在后还查 Redis？** 本地快照不知道其他实例刚新增的商家。共享新增集合用于关闭这个窗口；epoch 或集合丢失时放行，避免假阴性。
2. **Bloom 还有什么限制？** 100 万容量和 1% 是设计参数；误判仍可能回源。共享新增集合目前不清空，会随新增商家增长。外部直接写数据库不在保证范围内。
3. **为什么不让逻辑过期数据永久保留？** 项目保留物理硬期限，防止 Redis 长时间故障时无限返回旧值，也限制多级缓存层层续命。
4. **Redis 挂了为什么不全量回源？** 全量回源会把缓存故障扩大成数据库故障，所以使用 L1 短时旧值、每秒回源上限和并发信号量；超限返回 503。
5. **Outbox 是否保证消息只发送一次？** 不保证。发送后、标记前宕机会重复发布；业务幂等保证重复消息只有一次业务效果。
6. **Kafka 幂等生产者是否等于端到端 exactly-once？** 不等于。它减少生产重试重复，数据库事务和 Kafka 事务没有合成一个原子事务，仍需 Outbox 和业务约束。
7. **Redis 和 MySQL 怎么保证一致？** 不做跨库强一致。Redis 负责临时预占，MySQL 最终裁决；补偿任务、幂等状态机、超时任务和 epoch 恢复使状态最终收敛。
8. **为什么订单查询只做同库 32 表？** 目标是验证按用户路由、同步和补数，而库存与建单继续使用本地事务。直接拆物理库会引入跨库交易，且不能消除同一活动的库存热点。
9. **自动核对会不会覆盖新状态？** 核对只提升投影版本并重新排队；目标表只有更高版本能更新，迟到旧版本不能把 CONFIRMED/CANCELLED 改回 PENDING_CONFIRM。
10. **为什么不用 Snowflake？** 当前 UUID 已满足跨实例生成，查询按 user_id 路由，不依赖 ID 编码。没有完成 worker 租约和时钟回拨验证前，不把 Snowflake 写成成果。
11. **压测数字如何得到？** 双 JVM、每个 384MiB、总并发 8，128 个 Cookie 登录会话、20 个商家轮询，数据库直读、Redis TTL、多级缓存交错运行，每种预热后 30 秒，三轮取中位数。QPS 从 6,204 到 8,396，P95 从 1.882 到 1.707ms；基线有 5 次 503，保留原始失败记录。
12. **这个提升能代表整站吗？** 不能。它只代表商家基础信息接口；详情页还要查询优惠、库存和展示信息。旧版 2.34 倍使用单热点和测试令牌，不包含正常会话查库，不能与最新结果混用。秒杀写链路也有不同的瓶颈。
13. **为什么用 ZSet，还保留数据库任务？** ZSet 用于按时间找到到期订单，数据库任务保证重启或 Redis 数据丢失后仍能处理。ZSet 不是唯一事实来源，每 10 秒有分批到期扫描兜底。
14. **取出任务后进程崩溃怎么办？** 当前先查询到期成员，不提前删除。订单事务成功或发现终态后才移除成员；重复执行由条件状态更新挡住，数据库兜底也会重试。
15. **CAS 与行锁是否重复？** CAS 防止状态重复转换；活动行锁继续协调订单处理、库存回补和 epoch 恢复。不能只删除原有行锁而忽略其他库存写入路径。
16. **钱已经付了，关单先成功怎么办？** 不复活已关闭订单，记录渠道流水并在同一事务创建退款任务。模拟渠道退回这笔款；未来真实渠道接入也需要查单、关单和对账，单靠 CAS 不会自动退款。
17. **退款成功后服务重启，会退两次吗？** 使用固定渠道流水作为退款幂等键。模拟渠道退款账本先提交，本地任务再确认；再次执行同一流水不会生成第二笔退款。
18. **是否接入真实支付？** 没有。接口是受登录、CSRF 和用户归属保护的模拟通知，默认关闭。它覆盖并发与故障流程，不声称实现真实支付签名验证或真实资金清算。
