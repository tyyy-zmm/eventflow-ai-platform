# 校园抢票前端与模拟支付完善

日期：2026-10-09。产品场景统一为“趣票｜校园文体活动抢票平台”，沿用已有交易、缓存和可靠性实现。

## 改动

- 新增模拟支付窗口，展示金额、付款状态及退款状态；采用由付款 ID 派生的稳定通知标识，重试不产生新的付款流水。
- 响应丢失时通过付款查询恢复，关闭订单后可以重新打开付款记录。
- 默认保持确认订单模式；前后端均开启模拟支付开关时显示支付入口。
- 历史订单单独分页，不再与实时订单互相切换页码；清理读模型、分表等用户不需要了解的描述。
- 修复首页品牌链接，候补文案不再承诺严格按顺序补位。
- 首页、活动详情、票档、票夹、候补、规划和支付流程统一使用校园抢票语义；演示数据替换为音乐节、赛事、讲座、社团活动等 15 场校园活动。
- 新增舞台、球场、天文、手作、展览、讲座、正念和电影 8 组本地 SVG 活动封面，移除旧场景图片造成的视觉冲突。
- 抢票端采用常见票务 App 的信息结构：主推活动横幅、活动分类、热门开票、双列活动流、移动端底部导航和底部活动详情面板；支付窗口保持独立的安全提示样式。
- `bash run.sh dev` 默认同时开启前后端模拟支付，直接演示“抢票—支付—出票—超时关单—退款”。

## 验证

前端构建通过。真实验证后端使用 life_choice_verification、Redis DB 13、验证 Kafka topic/group。模拟付款不涉及真实资金，规划使用本地 stub。

- 9 组校园抢票浏览器回归全部通过：活动筛选、登录恢复、异步抢票出票、取消与限购、丢响应恢复、移动端、本地存储故障、账户隔离、规划。
- 新增 5 项检查通过：付款响应丢失恢复、支付后刷新、历史订单文案与手机布局、取消后到账退款、关闭订单重查退款。
- 浏览器运行时错误为零；桌面 1440×1000 与手机 390×844 已检查，票务 App 版截图保存在 `frontend/evidence/frontend-2026-10-09/ticket-app-flow`，支付截图保存在同级 `ticket-app-payments`。

## 使用

```bash
PLANNING_MODE=stub bash run.sh dev
```

生产构建的 VITE_SANDBOX_PAYMENTS 为构建期配置，需在构建时设置。后端关闭模拟接口时，前端会明确提示当前环境未开启。

浏览器验证使用 frontend/tests/payment-flow.mjs 和 customer-flow.mjs，需提供可用的 Playwright 环境。运行支付测试时，前端必须启用模拟支付。测试会在验证库创建演示账号和订单，不应针对生产环境执行。

## 范围

这轮完成校园抢票场景统一、活动封面、订单支付联调和移动端体验修复。底层数据库仍沿用 `shop`、`offer` 等历史命名，外部接口也保持兼容；用户界面已经统一为活动、票档和票夹。支付和退款均为模拟通道，没有接入真实支付机构。
